# GEOS 2.0 easter egg

At the BASIC prompt, enter `LOAD "GEOS",8,1`. Case and spaces around arguments are accepted. GEOS is intentionally absent from the BASIC disk listing.

The command shows SEARCHING / FOUND / LOADING in readable stages and opens a browser recreation of the English GEOS 64 2.0 deskTop after 3.6 seconds. No RUN is required for this easter egg. Reduced motion does not skip the static loading messages. Escape cancels loading.

## Included

- A fixed 320 x 200 bitmap desktop, proportional bitmap lettering, patterned background, fixed disk pad, eight files per page, folded page corner, disk drive and waste basket.
- All seven menu headings; icon and list views sorted by name, size, type or synthetic disk order/date.
- Single-click selection, Shift-click multiple selection, double-click or Enter to open, file information, rename, duplicate, protected system files, reversible deletion, disk open/close/rename/info and validation feedback.
- GEOS and deskTop information, shortcuts, input/printer information, configuration information, desktop pattern switching, calculator, current-time clock and editable Note Pad.
- Open dispatch uses explicit GEOS file types and a browser application registry. READ ME is a document associated with TEXT READER, which displays its full text in a scrollable, read-only window. Multiple selection is rejected by Open. System files and drivers report that they cannot be opened from deskTop; missing document applications offer Retry and Cancel. Page, view, disk and selection are restored when an application closes.
- The virtual disk saves automatically in this browser: file and disk names, copies, trash, file metadata/associations, desktop pattern, and Note Pad content survive page reloads. Each Note Pad accessory file owns its text, so copies can be edited independently. Existing BASIC saved programs use their original storage keys.
- disk > export downloads a JSON backup; disk > import opens a file picker and previews a validated backup before replacement. disk > previous disk offers the previous saved snapshot using the same preview. The disk retains one waste basket file and reserves its space so it can always be restored.
- file > new text creates a named plain-text document through Note Pad. The scratch Note Pad also has New and Save as controls. Named documents have explicit Save, Export (.txt), New, and Close controls; double-clicking their disk icons reopens them for editing. Ctrl/Cmd+S saves. Unsaved changes are checked on Close, New, return to BASIC, and browser reload/close.
- Tab / Shift+Tab and arrow keys move among controls; Enter / Space activate them; Page Up / Down turn disk pages. F1 opens shortcuts. Escape closes a menu/dialog or offers to return to BASIC. Alt+B offers to return to BASIC. The options > BASIC and file > quit commands do the same.
- BASIC input, paste handling and the maze screensaver are suspended throughout GEOS loading and use. Leaving restores the original prompt, BASIC program and colors, and restarts the idle timer.

## Scope and fidelity

This is an independently implemented web desktop, not a C64 emulator or a port of the GEOS kernel. It does not execute original GEOS applications. Local D64 images can be opened in a read-only directory viewer. geoWrite and geoPaint are not included as executable applications. The sample desktop's font glyphs and icons are drawn for this recreation; D64 files display icons read from the selected image when available. The sample disk contents and accessory dialogs are representative, not an exact distribution-disk image. Disk persistence is local to the current browser profile and origin; JSON export/import provides portable backups. Clearing browser site data removes local saves.

To keep the initial implementation bounded, hardware-related commands report the simulated configuration. Validate reports the simulated disk state. The clock shows the browser's local clock and has no alarm scheduling. Preference Manager shows available input/display controls; Pad Color Manager changes the desktop pattern. There is no hardware formatting, printing, file dragging or original disk I/O. List views use synthetic file metadata; by date follows the original sample disk order. The waste basket holds one file; moving another there restores the previous file to the simulated disk. Empty explicitly removes its current file after confirmation.

The Open dispatch follows the static investigation documented in [GEOS/OPEN-WORKFLOW.md](GEOS/OPEN-WORKFLOW.md). Browser application IDs, the sample TEXT READER association, case-insensitive filename lookup, Retry wording, and desktop-context restoration are implementation choices. Original GEOS binary applications and legacy PRG execution remain unsupported. Missing-application Retry checks the current virtual disk again. JSON backups are specific to this browser recreation. File icons do not determine application behavior. The local research disk images and extracted code are not website assets.

## Local D64 directory viewer

Choose **disk > open D64**, select a local `.d64` file, then confirm Open. For the supplied images, select `website/GEOS/GEOS Boot Disk.d64` or `website/GEOS/GEOWrite.d64`. The picker reads the image locally in the browser; it does not upload or publish the file. Image bytes are held only in memory, and a page refresh returns to the saved web disk. Original images remain unchanged.

This first version supports 35-track D64 files of 174848 bytes, including the 175531-byte variant with a sector-error table. Other sizes are rejected. It follows the directory chain with bounds/loop checks and includes occupied GEOS border-directory entries. Deleted slots are skipped. Disk labels, file names, DOS/GEOS types, block counts, sequential/VLIR structure, write-protection flags, valid GEOS timestamps and class names come from the image. Supported 24 x 21 monochrome icons are read from GEOS information sectors; unavailable/malformed icons use a generic icon and generate a metadata warning. ASCII-compatible mixed-case names, shifted spaces and high PETSCII letters are mapped; unsupported PETSCII graphics become question marks. This does not reproduce every PETSCII display mode.

The header uses real 254-byte block units, with free data blocks counted from the BAM bitmap, excluding track 18. Used blocks are 664 minus free blocks, not the sum of directory sizes. List-view sizes have a B suffix for blocks rather than Kbytes; file info spells out the unit. Date sorting uses valid recorded timestamps, with undated files first. **disk > info > Details** lists metadata warnings, including inconsistent BAM counts, unavailable info sectors, unclosed entries and flagged error-table sectors. File data chains and application contents are not validated; Validate makes this scope explicit.

The supplied boot image shows label `GEOS plain boot`, 15 directory entries and 209 free blocks. Its `DESK TOP` is GEOS type 4, VLIR, 120 blocks. The GEOWrite image shows label `geoWrite 64`, 30 entries and 25 free blocks. Its `GEOWRITE` is type 6, VLIR, 141 blocks, with class `geoWrite    V2.1` (so the application identifies itself as 2.1). These values describe the supplied images rather than an assumed stock GEOS 2.0 distribution.

Double-click/Enter on a supported geoWrite V2.0/V2.1 document opens its formatted text; other native files show metadata and explain that native execution is unavailable. The viewer blocks file/disk writes, web-disk imports, basket changes and browser accessory launches. Export downloads the exact original D64 bytes. **Web disk** at the bottom of the desktop, or **disk > web disk**, returns to the writable web disk with its files, basket, selection, page and view preserved. Opening a second image keeps that original web disk available. Returning to BASIC also detaches the image. Mounting does not save or overwrite any localStorage keys, and existing storage errors/tab-conflict safeguards remain in effect after returning.

Format references: the [GEOS Programmer's Reference Guide, Directory Structure and Information Sector Format](https://www.zimmers.net/anonftp/pub/cbm/geos/programming/documents/geostechref.html), and local mist64/geos `inc/const.inc` offsets at revision `617efdc7191eda14eaf699d317e66d5bda68c039`. The D64 reader is independently written JavaScript; this change does not claim REA analysis or native execution evidence.

Run `node --check script.js` and `node --test tests/geos-*.test.cjs` for 74 checks when both supplied images are present (72 checks plus two skipped image checks on a checkout without them). The D64 tests construct their own synthetic image and check real-image inventories locally, metadata/icons/dates, border and chained directories, malformed links/loops/headers/sizes, warnings/error tables, PETSCII fallback, read-only guards, exact-byte export, disk switching/context preservation, refresh/BASIC exit, denied storage, and asynchronous picker/import races. Actual browser picker/rendering behavior remains a manual check. Acceptance: open each supplied image, page through and switch to a list view, inspect GEOWRITE, export it, then choose Web disk and verify existing notes and pictures reopen.

## Original geoWrite document reading

Open a D64 containing a GEOS type 7 VLIR document with class `Write Image V2.0` or `Write Image V2.1`, then double-click it. The reader displays text with bold, italic, underline, font size and monochrome embedded pictures, with Prev/Next for pages and separate header/footer sections. Details explains omitted formatting and any decoding warnings. Export downloads all extracted sections as a `.txt` file. The original image and writable web disk remain unchanged. Earlier/unknown document versions, geoPublish documents and native programs still show metadata.

Paragraph alignment, margins and first-line/hanging indentation are approximated from ruler records. Original font bitmaps and widths can be loaded locally with disk > load fonts. Matching font ID/size pairs use their original shapes and advances; missing matches use a browser font. Print pagination is not reproduced. Embedded monochrome pictures are decoded from Photo Scrap records, kept in text order and shrunk to fit the viewer width. Unreadable pictures retain a placeholder and a warning in Details. Color is ignored. Sizes map to pixels before desktop scaling, with zero-size codes using a 10-pixel fallback. Reverse, outline, superscript and subscript are omitted. Text remains selectable and read-only, and Export remains plain text. Invalid chains, overlapping sectors, recorded read errors or truncated escapes report a decode failure. This feature interprets document data and does not run the geoWrite application. See [decoder rules and validation evidence](GEOS/GEOWRITE-READER.md) for references and limits.

Neither supplied disk contains a geoWrite document. For local acceptance, `GEOS/research/collette.s1.d64` was downloaded from the public [Collette Utilities archive](https://www.zimmers.net/anonftp/pub/cbm/geos/util/ColletteUtils_d64.zip); open it with disk > open D64 and double-click `Font Editor.doc`. The downloaded research images are not site assets. `GEOS/research/geoWrite-reader-demo.d64` is an independently constructed test disk with two sample pages and header/footer sections, generated from the committed test helper. All 129 automated checks pass locally, including smoke extraction of 26 historical documents across the two public archive disks. Actual live rendering still needs a manual check.

For paragraph layout acceptance, open `GEOS/research/geoWrite-paragraph-demo.d64` and double-click READ ME. It contains a centered heading, left/right/justified paragraphs and a hanging indent. Coordinates scale to the viewer width with a 480/640-dot width inference, while browser fonts determine wrapping. Regular and decimal ruler tabs and single/1½/double line spacing are supported; print pagination remains unsupported. Invalid or misplaced rulers add warnings; exporting text and returning to Web disk preserve the existing behavior.

To load original fonts, choose **disk > load fonts**, select `GEOS/GEOWrite.d64`, then close the font summary. Open a document D64 normally. The supplied disk has 22 usable font sizes, including California 10/12/14/18. Imported fonts remain available while switching disks or returning to BASIC, until the browser page is refreshed. They do not replace either disk or enter the saved web-disk JSON. The reader status distinguishes GEOS, mixed and browser fonts; Details lists matches and fallbacks. Fonts are read locally, converted into in-memory browser font wrappers and registered through FontFace. No original font files are published with the site. Bold/italic use browser synthesis and may differ from GEOS.

For a focused live check, after loading fonts open `GEOS/research/geoWrite-font-demo.d64` and double-click READ ME. It exercises all four available California sizes and style combinations. This is a constructed document; the fonts come from the separately selected original image. The same font load improves supported sizes in the historical Collette documents. Missing fonts continue to display through the fallback.

Ruler tabs preserve up to eight positions and distinguish regular from decimal stops. The English decimal separator is a period; an integer field aligns its right edge. Positions scale to the paragraph width, while numeric-prefix widths use loaded GEOS metrics or measured browser text. Missing/exhausted stops use a four-space fallback. Centered/justified/right-aligned or heavily wrapped tabbed lines remain approximations. Invalid stops are skipped with a warning; source tab characters remain in plain-text export. To check columns, load fonts from `GEOS/GEOWrite.d64`, open `GEOS/research/geoWrite-tabs-demo.d64`, double-click READ ME and compare the quantity column and the aligned amount decimal points.

## Plain-text documents

Use file > new text, type, click Save, and enter a unique name of up to 16 characters. The saved file is selected and brought into view when the editor closes. Double-click it to reopen, edit, and Save or press Ctrl/Cmd+S. file > duplicate creates an independently editable copy with a distinct generated name. Changes to a named document are drafts until saved; the asterisk and status line indicate unsaved changes. New, Close, and return to BASIC offer Save, Discard, and Cancel when needed. The browser's reload/close warning is requested for unsaved text. Protected documents open read-only.

The original scratch Note Pad still autosaves its own text. Its New button starts a blank document; Save as copies the scratch text into a named document without changing the scratch note. Named documents associate with the current Note Pad filename on the same virtual disk, so renaming or removing that accessory can require restoring its name before a document will open. Allowing this browser Note Pad accessory to act as a document application is an intentional extension to the original GEOS file-type dispatch, not recovered original behavior. READ ME continues to open read-only in TEXT READER. Existing disk saves need no schema upgrade or reset.

Document sizes are recalculated from UTF-8 text when saved, within the virtual disk's capacity. A full disk, blocked storage, or conflicting saved disk leaves the draft open and the previous saved document unchanged; Export downloads the draft as a plain `.txt` file for recovery. Disk JSON export includes saved document contents and associations, not unsaved editor drafts. Formatting and native geoWrite editing are not implemented. Supported original geoWrite documents can be read from D64 images as described below.

## Disk storage and recovery

The `c64-geos-disk` localStorage key contains a `geos-web-disk` version 2 snapshot (version 3 when pictures are present) with disk identity/name/pattern, file records, and a nullable waste basket file ID. Note Pad text is the accessory file's `content`; documents retain their text and parent-application association. The first save migrates text from the old `c64-geos-note` key without deleting or updating that legacy key. Version 1 disk snapshots are upgraded by moving their optional top-level `note` into the Note Pad file, with a missing pattern and trash ID defaulting to zero and null. Original version 1 bytes are retained as the previous snapshot.

Each successful change retains the previous saved snapshot in `c64-geos-disk-backup`; this is one rotating snapshot, not full history. Import keeps the current in-memory disk as that backup before writing the replacement. Invalid import files do not change the disk. Confirmation is canceled if another tab has changed the saved disk; reload before importing again. Import accepts only the supported schema, unique file IDs, valid text/metadata, and the simulated 165-Kbyte capacity, including the trash reservation. It does not execute content from a backup.

If the main save is corrupt or from a newer unsupported version, a readable previous snapshot is loaded when available, and automatic writes are blocked to preserve the original bytes. Use disk > previous disk to review and explicitly restore that snapshot, or import a known backup. Replacing an unreadable/newer primary save also preserves its raw bytes in `c64-geos-disk-recovery`. This recovery key is for manual recovery with a compatible future version. If both saved copies are unreadable, the supplied sample disk is shown in session mode and both saved copies remain unchanged.

Storage denial, quota failures, and conflicting tabs leave the current session usable. The desktop shows `session only`, Note Pad reports its save status, and disk > info gives the reason. Export remains available for session data. An import that cannot be saved leaves the current disk unchanged. Disk saves do not include BASIC programs, browser history, open application state, or page/view/selection across full reloads. App close/return still preserves its desktop context within the current session.

## Emptying the waste basket

Open the waste basket to Restore, Empty or Cancel. It shows the current file and the space it holds. **Empty** opens a second confirmation showing the file name and KB to reclaim; Cancel or Escape returns to the basket without deleting anything. **disk > empty basket** opens the same confirmation directly. An empty basket reports that it is empty. Protected files cannot be emptied.

Confirmation removes the file record and its contents, clears the basket and saves the disk. The desktop's used/free counters immediately reflect the reclaimed capacity, which can be used for new documents or copies. The deletion survives reload. If saving fails, including a stale-tab conflict, both the in-memory file and basket entry are restored; no space is reclaimed. Restore also retains the basket entry if its save fails.

The normal rotating previous snapshot is retained before emptying. Immediately afterward, **disk > previous disk** can restore the entire preceding disk; subsequent saves replace that rotating snapshot. Export a disk backup before emptying if a lasting recovery copy is wanted. This is a web disk feature, not evidence of the original deskTop's deletion behavior.

`node --test tests/geos-*.test.cjs` runs all 61 checks. Six basket checks cover confirmation, reclaimed capacity and reload, Cancel/Escape/Restore, empty/protected baskets, primary/backup write failures, conflicting tabs, and recovery from a saved snapshot. ## Paint

Choose **file > new picture**, or open **PAINT**. On an existing saved disk, new picture installs the 4 KB browser application if space and writable storage are available. Existing files remain on the disk. The canvas is 128 x 56 pixels, enlarged twice inside the 320 x 200 desktop. Select pencil, white eraser, contiguous fill, line or outlined rectangle, and one of eight colors. Drag with a mouse, pen or touch. Undo retains the last twelve drawing operations. Keyboard users can focus the canvas, move with arrows and draw with Space; for line/rectangle press Space at the starting point, move with arrows, then press Space again.

Save (or Ctrl/Cmd+S) creates a named, 7 KB document associated with the application. Reopen the picture from deskTop, including after refresh. Copies edit independently. New, Close and BASIC exit offer Save/Discard/Cancel for changed pictures. Reload requests the browser's native unsaved-change warning. Locked pictures can be viewed and exported. Unsaved drafts stay in memory until saved or exported. Export downloads a portable SVG of the current picture; reopening editable pictures uses the web disk, not SVG import.

Disk export/import includes picture dimensions and validated palette indices. Disks containing pictures use snapshot version 3 so older site code rejects the save instead of silently discarding picture data. This release continues to read versions 1 and 2. Full disks, storage errors and tab conflicts retain the draft and last saved picture. Paint's SVG export remains available if saving fails.

This is a browser paint implementation, not original geoPaint binary execution or its native document format. ## Ruler line spacing

The [primary geoWrite ruler description](https://www.pagetable.com/242) assigns bits 2–3 of ruler byte 23 to single (0), 1½ (1), and double (2) spacing. The reader preserves alignment in bits 0–1 and carries spacing across paragraphs until the next ruler. Each text record (page/header/footer) starts with single spacing. Reserved value 3 falls back to single and adds a ruler warning; invalid geometry resets the entire ruler. A mid-paragraph ruler applies at the next paragraph boundary with the existing warning.

Paragraphs use unitless CSS line heights of 1, 1.5 or 2, so mixed-size text contributes its own font metrics. Blank paragraphs receive a minimum height based on their active font size and spacing. Browser baselines, wrapping and synthesized styles remain approximations of native GEOS. Text export, source D64 bytes and web-disk storage are unchanged.

Five new controller/decoder checks cover spacing/alignment independence, reserved values, persistence and invalid/misplaced rulers, mixed fonts and blank paragraphs, section resets/navigation and unchanged export/storage/bytes. All 129 Node checks pass locally. These tests use a DOM substitute; visual spacing remains a manual acceptance check.

For live acceptance, load fonts from `GEOS/GEOWrite.d64`, open `GEOS/research/geoWrite-spacing-demo.d64`, then double-click READ ME. Its three pages contain the same sample text at single, 1½ and double spacing. Use Next/Prev to compare the gap between wrapped lines. The constructed demo stays local and contains no original font data.
